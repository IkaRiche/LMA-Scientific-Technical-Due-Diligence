# Reviewer challenge cards — evidence questions, not implementation instructions

**Purpose:** give external technical specialists a falsifiable discussion plan without providing algorithms, private sources, raw sensor data or operational parameters. These are questions for a preliminary assessment, **not** instructions to run new experiments.

Use the [focused screen](11_FOCUSED_AUTONOMY_REVIEW.md) and [review protocol](05_REVIEW_PROTOCOL.md). The owner retains custody of any demonstration. Reviewer may record `EVIDENCE_INSUFFICIENT` if undisclosed information is essential.

## Card A — decentralized decision ownership

**Claim under review:** a bounded digital two-organism cooperation effect depends on local organism states and peer interaction, not a runtime global allocator.

- **Strongest alternative:** a simulator host computes or assigns the meaningful response; the organism layer only relabels that selection.
- **Reviewable questions:** Which facts originate in an organism's own state? Which arrive from local observations? Which are peer signals? Is the host restricted to simulated world/observation/execution functions?
- **Discriminator already reported:** preregistered removal of necessary peer/observation/plant/confirmation links changes the frozen outcome, while replay is deterministic.
- **Limits:** the simulation still uses a shared world model. A claim about arbitrary physical decentralized systems remains unsupported.
- **Decision:** decide whether the stated *scoped mechanism* is credible or whether a private source audit is indispensable.

## Card B — coordinate-free communications versus coordinate-free meeting

**Claim under review:** the accepted peer path need not transport coordinate or action-assignment payloads.

- **Strongest alternative:** essential geometry or response decisions are hidden in a peer payload, a simulator-side control plane, or privileged local inputs.
- **Reviewable questions:** What is the actual permitted peer-message class? What source supplies local observations? Are there separate peer information paths in older experiments? Is the result message required for the other organism to observe recovery?
- **Discriminator already reported:** the scoped peer event ledger and causal controls distinguish the LMIO pathway from auxiliary functional-result traffic.
- **Independent synthetic donor:** a civilian moving-service-station study explores local feedback without coordinate payloads to a rover; positive and negative outcomes are both retained.
- **Limits:** neither experiment establishes a universal mathematical meeting-point calculation from LMIO alone; local geometry is permitted, hardware sensing unverified, and native integration absent.
- **Decision:** approve only the narrower communication-path proposition. Mark the general meeting-point proposition **NOT_ESTABLISHED**.

## Card C — persistent terminal mission conduct

**Claim under review:** a bounded TMC retains one externally assigned mission goal, updates its continuation after admitted outcomes and ends in either an explicit terminal condition or principled refusal.

- **Strongest alternative:** the host supplies the next route or a conventional controller with the same information produces an identical result.
- **Reviewable questions:** Was the goal retained? Were output choices conditioned on native acquired history? Could external route labels or resume indices leak into replanning? Was external execution authority separated?
- **Reported controls:** fixed-goal and topology intervention, history effects, stale-continuation rejection, conventional full-information parity, stable replay and zero execution authority.
- **Hardware scope:** two matched STM32H723 bench decision traces in one frozen test; no general timing or real mission qualification.
- **Decision:** distinguish scoped mission-computation evidence from flight readiness and from the untested combined Veil/TMC application.
